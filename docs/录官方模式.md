# 怎么自己录官方模式

> 目的：把官方 App 里那十几个花样模式的真实数值序列抓下来，一比一复刻进本项目的花样引擎。
> 原理：安卓手机有个开发者开关，能把所有蓝牙收发记进一个日志文件；官方 App 每个模式跑一分钟，
> 日志里就留下它每一步发出去的数值。拿到日志后用 `tools/extract_patterns.py` 按公式反推即可。
>
> 下面的菜单名字以 vivo / iQOO（Android 14）为准，其他品牌位置略有不同，关键词一样。

## 第一步：打开手机的蓝牙日志开关（一次性）

1. 设置 → 关于手机 → 连续点「版本号」7 次，直到提示「已处于开发者模式」。
2. 设置 → 系统管理 → 开发者选项（vivo 有的在「更多设置」里）。
3. 找到「启用蓝牙 HCI 信息收集日志」（有的叫「蓝牙 HCI 日志」），打开。
4. 关一次蓝牙再打开，让开关生效。

## 第二步：跑模式

1. 退出本项目的「失控桥」App，以及任何别的会发广播的程序，确保只有官方 App 在发。
2. 打开官方 App（或小程序），连上玩具。
3. **一个一个来**：选第 1 个模式，吮吸端和入体端都点上，让它跑满 60 秒；点停；等 10 秒。
4. 换第 2 个模式，同样跑 60 秒、停、等 10 秒……直到所有模式跑完。
5. 顺手记一张单子：模式的**顺序和名字**（「1 玄妙 2 暗涌 3 ……」），后面提取时要按这个顺序传参。

> 提取脚本以「总关」命令作为一个模式的分界，所以每个模式之间**必须点停**。
> 中途手滑、没跑完的段会被自动丢掉，不占名字的顺序。

## 第三步：把日志导出来

1. 开发者选项 → 「错误报告」→ 选「完整报告」→ 确定。等通知栏出现「错误报告已生成」（几分钟）。
2. 点那条通知 → 分享 → 发到电脑，是一个 .zip。
3. 解压后日志一般在 `FS/data/misc/bluetooth/logs/btsnoop_hci.log`，把它传到服务器上。

## 第四步：提取成 patterns.json

```bash
python3 tools/extract_patterns.py btsnoop_hci.log 玄妙 暗涌 旧梦 ... -o patterns.json
```

- 模式名按第二步记的顺序一个个写上去，脚本按分段顺序对号入座。
- 加 `-v` 会打印每段完整时间线，用来人工核对有没有错位。
- `tools/parse_timeline.py <日志>` 是个更原始的工具，直接打印每一条广播命令和时间戳，排查用。

生成的 `patterns.json` 放到服务器的 `/opt/shikong-bridge/patterns.json`，重启 `shikong-relay` 即生效。

## 第五步：关掉日志开关

录完记得回开发者选项把「蓝牙 HCI 日志」关掉，不然它一直在记，占空间。

---

**解析细节**：只看 `LE Set Advertising Data` / `LE Set Extended Advertising Data` 命令里的
0x07 段（128 位 UUID），按 `docs/接口约定.md` 第 7 节的公式反推 level，再按时间戳切成序列。
