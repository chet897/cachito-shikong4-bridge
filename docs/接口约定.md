# 失控 4.0 手机广播控制 · 接口约定（VPS 服务 ⇄ 安卓 App 共用）

> 两边的实现都以本文为准；改本文必须服务端和 App 同步改。
> 背景：失控 4.0 不走蓝牙连接，靠"广播"控制；手机浏览器发不了广播，所以做一个安卓 App 常驻后台发广播。
> 链路：AI → 失控 MCP（VPS:8896）→ 中转服务（VPS:8895）→ WebSocket → 安卓 App → 手机蓝牙广播 → 失控 4.0

## 1. 端口与地址

| 组件 | 位置 | 说明 |
|---|---|---|
| 中转服务 relay | VPS `0.0.0.0:8895`（aiohttp） | 唯一真身状态机 + 花样引擎 + WebSocket + 手动网页 |
| MCP 服务 | VPS `0.0.0.0:8896`（FastMCP streamable-http，路径 `/mcp`） | 给 AI 用；内部用 localhost HTTP 调 relay |
| 对外入口 | `https://YOUR_DOMAIN/shikong/...` | 用 Cloudflare Tunnel 时加一条 path 规则指到 8895（要放在更宽的通配规则之前）。App 里 WebSocket 用 `wss://YOUR_DOMAIN/shikong/phone/ws` |
| 备用入口 | `http://YOUR_VPS_IP:8895/...`、`ws://YOUR_VPS_IP:8895/phone/ws` | 防火墙放行 8895；App 设置页允许改地址 |

relay 收到的路径统一**先剥掉 `/shikong` 前缀**再路由（隧道过来带前缀，直连不带）。

## 2. 口令

- 单一口令，存 VPS `/opt/shikong-bridge/token`（自己生成，推荐 `openssl rand -hex 8`）。relay 和 MCP 服务**启动时读**它，换口令后两个都要 restart。
- App：**不内置口令**（0.1.2 起；旧版内置口令被腾讯扫描沙箱拿到过），首次启动手填，设置页可改。
- 携带方式：WebSocket 用 query `?token=...`；HTTP 用 header `Authorization: Bearer <token>` 或 query `?token=`。
- MCP 服务在 VPS 本机调 relay，用同一口令。
- 缺口令/错口令一律 401。

## 3. 状态模型（relay 是唯一真身）

```json
{
  "suck":  {"level": 0, "pattern": null},
  "invib": {"level": 0, "pattern": null},
  "seq": 123,
  "phone_online": true,
  "phone_last_seen_ms": 1789000000000
}
```

- `level` 0-100，App 滑块刻度；0 = 关。
- `pattern` 是模式名或 null。模式在跑时，relay 每一步把该通道 `level` 改成序列当前值并推给手机；手动设 level 会把该通道 pattern 清成 null。
- 两个通道完全独立，可以各自跑不同模式（对齐官方 App：每个模式旁边有"吮吸端 / 入体端"两个按钮，可任意搭配）。

## 4. WebSocket 协议（relay → App）

地址：`/phone/ws?token=...`。一个手机同一时刻只允许一条连接，新连接顶掉旧的。

服务器推送（每次状态变化立即推；另外每 5 秒推一次心跳）：
```json
{"type": "state", "seq": 124, "suck": 40, "invib": 0}
{"type": "ping", "ts": 1789000000000}
```

App 回报：
```json
{"type": "hello", "app_version": "0.1.0", "device": "iQOO Z8", "connectable": true}
{"type": "ack", "seq": 124}
{"type": "pong", "ts": 1789000000000}
{"type": "error", "message": "advertise_failed_2"}
```

App 断线重连后先收到一条完整 state，以 relay 为准覆盖本地。

## 5. App 内部行为（广播层）

- 每次 state 变化：把 suck/invib 各编成一条 128 位 UUID 命令（协议见第 7 节）。
- **两条都非零时轮播**：suck 播 400ms → invib 播 400ms → 循环（玩具是 latch 型，收到一次就一直执行，时分复用等于同时）。只有一条非零就持续播那一条。
- **level 变成 0 时**：该通道播对应的"关"命令至少 1.2 秒（suck 用「吮吸关 01 00」；invib 单独关命令没抓到，用「总关 02 00」并在之后把 suck 重新播一遍恢复），然后停播该通道。
- **两个都 0（全停）**：先播「吮吸关 01 00」1.2 秒，再播「总关 02 00」1.5 秒，然后停止广播。（实测「总关」只关得住入体端，吮吸必须单发「吮吸关」。）
- 广播参数：`ADVERTISE_MODE_LOW_LATENCY`、`TX_POWER_HIGH`、`setConnectable(true)`（Esther 实测大秀/失控要可连接广播才认；设置页留一个"可连接"开关以防某些手机不行）、`AdvertiseData` 只含一个 128 位 service UUID，不带设备名。
- 前台服务（通知栏常驻），WebSocket 断了每 3 秒重连；本地保留最后一次 state，**断网不影响已经在播的命令**。
- App 界面（0.1.4 起分两页，页签切换）：
  - **连接页**：四行链路灯（口令/后台服务/VPS 连接/蓝牙广播，错误原样显示）、启停后台服务按钮（**不自动启动**）、设置入口、vivo 后台提示。
  - **控制页**（照搬 relay.html）：手机在线灯 + 最后指令；吮吸/入体各一个滑块 + `0/10/…/100` 快捷档位按钮（**本地优先**：150ms 节流直驱广播，再异步 POST `/api/set`；relay 回声一致则忽略）；模式卡（进页面拉 `GET /api/patterns`，每个模式三个小按钮「吮吸端/入体端/两端」→ `POST /api/pattern`，顶部「停模式（档位保持）」→ `POST /api/pattern/stop`，**因为 WS 推的 state 没有 pattern 字段，靠每 2 秒 `GET /api/state` 拿高亮**）；底部普通大小「全停」（先本地播关命令序列，再通知 relay）。
  - 设置页：地址、口令、可连接开关。收到 `{"type":"kicked"}` 显示"被另一台手机顶下线"并把重连间隔放到 15 秒。
- vivo/iQOO 需要用户开"后台高耗电允许 / 自启动"，App 首页给一条提示。

## 6. HTTP 接口（relay）

全部需要口令。

| 方法 路径 | 用途 | 请求/返回 |
|---|---|---|
| `GET /api/state` | 查状态 | 返回第 3 节 JSON |
| `POST /api/set` | 手动设档 | `{"suck": 40}` / `{"invib": 30}` / 两个都给；0 = 关；会清掉该通道 pattern |
| `POST /api/pattern` | 跑模式 | `{"part": "suck"|"invib"|"both", "name": "暗涌"}` |
| `POST /api/pattern/stop` | 停模式 | `{"part": "suck"|"invib"|"both"}`，档位保持当前值 |
| `POST /api/stop` | 全停 | 两通道 level=0、pattern=null |
| `GET /api/patterns` | 列模式 | v2：`[{"name":"暗涌","desc":"...","official":true,"suck":[[40,1.5],[10,3],[60,1]],"invib":[[35,3],[65,2],[25,3]],"suck_text":"40档×1.5秒 → …","suck_cycle_s":5.5,...}]` |
| `GET /` | 手动控制网页 | 手机浏览器打开 `https://YOUR_DOMAIN/shikong/?token=...`，两个滑块 + 全停 + 模式按钮 |
| `GET /app.apk` | 下载安装包 | 无口令但路径带随机段：`/app-<8位随机>.apk`，随机段写在 `/opt/shikong-bridge/apk-path.txt` |

## 7. 蓝牙协议（失控 4.0，来自 Esther7314/cachito-ble-control，抓包验证过）

一条命令 = 16 字节 = 一个 128 位 UUID（字符串形式 `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`，字节顺序就是从左到右）：

```
[0]71 [1]00 [2]17 [3]nonce [4-5]类型 [6]9E [7]D5 [8-9]01 00 [10-14]载荷 [15]校验和
校验和 = 前 15 字节之和 mod 256；nonce 每条随机 0-255
```

| 命令 | 类型 b4-5 | 载荷 b10-14 | 参数 |
|---|---|---|---|
| 吮吸 | `51 00` | `64 00 00 [b13] 02` | `b13 = 50 + level//2`（level 1-100 → 50-100） |
| 吮吸关 | `01 00` | `64 00 00 00 02` | |
| 入体震动 | `52 00` | `2D [b11] 15 00 02` | `b11 = 102 - level`（**越小越猛**） |
| 总关 | `02 00` | `00 00 00 00 00` | |

自检样本（同 nonce 必须逐字节一致）：
```
suck(25,  nonce=0x63) = 71001763-5100-9ED5-0100-6400003E0254
suck(100, nonce=0x6F) = 7100176F-5100-9ED5-0100-640000640286
suck_off(nonce=0x1F)  = 7100171F-0100-9ED5-0100-640000000282
invib(50, nonce=0x66) = 71001766-5200-9ED5-0100-2D341500022C
invib(100,nonce=0x3F) = 7100173F-5200-9ED5-0100-2D02150002D3
off(nonce=0x77)       = 71001777-0200-9ED5-0100-000000000075
```

## 8. 花样引擎（relay 内）

- **v2 格式（2026-09-14 抓包后改定）**：每个模式两条序列，每步 `[level, seconds]`，**每步时长各自不同**（官方就是这样，不是固定节拍）；`part` 决定套到哪个通道；两通道各自独立循环。
- `patterns.json` 示例：`{"name":"暗涌","desc":"…","official":true,"suck":[[40,1.5],[10,3],[60,1]],"invib":[[35,3],[65,2],[25,3]]}`。旧格式（`seq`+`step_s`）仍兼容。
- 官方模式来源：用户手机开蓝牙 HCI 日志录官方 App，`/opt/shikong-bridge/captures/extract_patterns.py` 自动提取（步骤见《录官方模式》）。已装：玄妙、暗涌、旧梦（2026-09-14）。
- 每步只推 state 给手机一次；手机端负责持续广播。

## 9. MCP 工具（给 AI，8896）

| 工具 | 参数 | 说明 |
|---|---|---|
| `shikong_suck(level)` | 0-100 | 吮吸端手动档，0 关 |
| `shikong_invib(level)` | 0-100 | 入体端手动档，0 关 |
| `shikong_pattern(name, part="both")` | 模式名，part = suck/invib/both | 跑官方模式，两端可各选各的 |
| `shikong_pattern_list()` | | 列出模式 |
| `shikong_stop()` | | 全停 |
| `shikong_status()` | | 当前档位、模式、**手机是否在线**（不在线要明确告诉 AI"手机 App 没连上，命令发不出去"） |

工具描述里要写清：level 是 App 滑块刻度；玩具是记忆命令型，必须主动 stop；手机不在线时命令会排队等手机上线后生效。
